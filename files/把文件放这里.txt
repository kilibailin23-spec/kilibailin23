把你的下载文件（PDF、ZIP、EXE、PPT……）直接丢进这个 files 文件夹。


——————————————————————————————
放好之后：双击「更新下载列表.bat」
——————————————————————————————

项目根目录有个「更新下载列表.bat」，双击它。

它会扫一遍这个文件夹，自动把 data/files.js 的下载清单重新生成好 ——
文件名、所在文件夹、文件大小全都是自动的，不用手写。跑完还会问你要不要
提交并推送到 GitHub，按 y 就顺手推上去，Netlify 一两分钟后自己更新。

加了新文件、删了旧文件、换了文件内容，都是双击一下的事。


——————————————————————————————
分文件夹
——————————————————————————————

在这个文件夹里建子文件夹，把文件分门别类放进去。现在就是这么分的：

  files/
    game/
      弹球.zip
      小丑牌.zip
      pico park.zip
    联机补丁/
      dotnet-runtime-9.0.9-win-x64.exe
      机械狂潮补丁.zip

下载页第一层就会列出「game」「联机补丁」「未分类」，点进去才看到里面的
文件，标题右边显示「文件下载 / game」，点「文件下载」退回上一层。

放完新的子文件夹，双击一次「更新下载列表.bat」，下载页上就长出来了。

⚠️ 文件夹是按「里面有哪些文件」算出来的，不是真去翻文件夹 ——
建个空文件夹、里面不放东西，下载页上不会出现。


——————————————————————————————
想改显示名、加说明、或者挂网盘外链
——————————————————————————————

这些脚本管不了，得手动改 data/files.js。找到 FILES 那一段，照着格式写：

  const FILES = [
    {
      name: '我的简历.pdf',              // 显示的名字
      file: './files/我的简历.pdf',       // 相对路径
      size: '320 KB',                    // 留空也行，脚本会算
      time: '2026-09-21 15:30',          // 登记时间，排序用，可留空
      desc: '一句话说明'                  // 可留空
    }
  ]

你改过的显示名（name）和说明（desc），脚本会原样保住，重跑不会被覆盖；
只有 size 每次都会按文件实际大小重算。

time 是「登记时间」，下载页按时间排序靠它，格式固定成长这样：

  2026-09-21 15:30

必须写成这个格式（位数不够就补 0）—— 下载页就是拿字符串直接比大小的。
脚本生成的新条目会自动填上当时的时刻，之后再也不动，所以它记的是「这个文件
什么时候被登记进来的」，不是它在你硬盘上什么时候改过。手写的条目可以整个
不写这个字段，只是按时间排序时会沉到最底下。

file 直接写 https://… 的「外链条目」不归脚本管，原样留着，不会被删。

⚠️ 别在 FILES = [ ... ] 数组「里面」写注释，脚本重新生成时会没。
   数组上面那段注释不会动，随便写。


——————————————————————————————
注意几点
——————————————————————————————

1. 路径一律 ./files/ 开头（脚本生成的就是这个格式）。别写成 /files/，
   那是绝对路径，网站要是部署在子目录里会 404。

2. 文件名里有空格（像 pico park.zip）、有中文，都没问题。

3. GitHub 单个文件上限 100MB，超了推不上去。更大的文件建议传网盘，
   下载条目里的 file 字段直接写网盘链接 —— 但那样就没有 download
   属性了，点了会在新标签页打开，而不是直接下载。

4. ⚠️ 下载页上那个「+ 上传文件」按钮「不是」把文件存到这里来。
   它只是把文件读进你「自己这台电脑的浏览器」里（localStorage，一个
   只有几 MB 的小仓库）。别人打开你的网站看不到、也下不到这些文件，
   换台电脑、清一下浏览器数据也就没了。

   想让所有人都能下载，文件必须真的放进这个 files 文件夹，再双击
   「更新下载列表.bat」推上去。

5. 这个说明文件本身不会被列进下载清单（脚本跳过了它）。
