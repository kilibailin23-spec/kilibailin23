一个不用构建、不装依赖的静态博客。拆成了几个文件，改完直接传上去就能用。

## 一、线上预览

**双击 `https://kilibailin.netlify.app/` 就能看** —— 图标、背景图、主题切换都正常。

唯一会出问题的是「下载」页面里的文件链接：`file://` 协议下浏览器会拦掉
`<a download>`，点了没反应。要试下载功能的话起个本地服务器：

```bash
cd E:\9981\kili白麟
python -m http.server 8000
```

然后浏览器打开 https://kilibailin.netlify.app/ 。

（装了 Node 也可以用 `npx serve`。Python 的话 Windows 上大概率已经有了，
没有就去 python.org 装一个，勾选 "Add to PATH"。）

## 二、怎么改内容

内容都拆在 `data/` 文件夹里，一个东西一个文件。用记事本、VS Code、Notepad++ 都行。
最常改的是 `data/site.js` 和 `data/posts.js`：

> 💡 **懒得开编辑器？** 文章、作品、文件、网站导航都能在网页上直接改 ——
> 长按顶栏左上角那个方块 3 秒，点齿轮打开「开发者模式」，
> 页面上会直接长出「写新文章」「编辑」「删除」这些按钮，点开就能改。
> 改完立刻能看到效果，但**只存在你自己这台电脑的浏览器里**，
> 别人访问你的站看不到，清掉站点数据也没了。
> 它的定位是「草稿台」：在页面里改顺了，再把结果抄进 `data/*.js` 里重新部署。
> 详见后面「开发者模式」一节。
>
> 下面几节讲的是**改文件**这条路，也是唯一能让所有人都看到的那条。

### ① 站点信息 `SITE`

站名、一句话简介、邮箱、GitHub 地址。**先把 `SITE.email` 和 `SITE.github` 换成你自己的**，
不然「关于」页和页脚会链到 `example.com`。

首页最上面那一大块（横幅 → 关于我 → 联系方式）的内容也在这个文件里：

```js
avatar: null,                  // 你的头像，比如 './avatar.jpg'（正方形效果最好）
                               // 不填，或者图片加载不出来，就显示 SITE.mark 那个字
avatarBack: null,              // 头像**翻面**那张。首页头像点一下会像硬币一样翻 180°，
                               // 翻过去看到的就是这张；不填就退回用 avatar（翻过去还是
                               // 同一张，看着像卡住了）。想玩这个效果两张都得填。
avatarName: '白麟',             // 头像**下面**那行小字，用来写昵称。不要就写 null
greeting: '嗨，很高兴见到你 👋',   // 头像右边那行大字
hashtags: ['一行一条', '自我介绍'],  // 大字下面的几行小字
signature: '宁鸣而死，不默而生。',   // 右侧那列的手写签名
signatureTo: '— 白麟',          // 签名的落款，不要就写 null
```

**顶上那行大字（横幅里的「艺术字」）**：

```js
banner: 'Blog Of BaiLin',   // 写什么显示什么，英文、繁体、日语、符号都行
bannerFont: '"Microsoft YaHei",ui-sans-serif,system-ui,sans-serif',
bannerSize: null,           // 例如 '4.2rem'；null = 用默认的自适应字号
```

`bannerFont` 想玩花体就换成系统里装了的字体：

```js
'"Segoe Script",cursive'         // Windows 自带的英文手写体
'"Old English Text MT",serif'    // 哥特体（装过 Office 才有）
'"华文行楷","STXingkai",cursive'  // 中文行楷
```

> ⚠️ 字体得是**看网页那台电脑上装了的**才有效。这个站零依赖、不联网加载任何东西，
> 所以别指望从网上下个字体文件在这里能显示 —— 网页字体（`@font-face`）这套它不走。
> 想固定一款字体，唯一的办法是让看的人自己也装了。

**顶栏左上角那个方块**（默认显示 `mark` 那个字，也就是「白」）：

```js
markImg: null,   // 换成 './logo.png' 之类的图片路径
```

填了它之后，方块里显示的是图片，`mark` 那个字退到图片底下当兜底。
建议用正方形 —— 方块本身是 `42×42`，四个角会被裁圆。

> 💡 **三处「第一字占位」都能换成图片**，走的是一模一样的套路：
> 顶栏方块（`markImg`）、首页头像（`avatar`）、文章卡片封面（`POSTS[].cover`）。
> 三处都是**字先渲染出来当底、图盖上去**，图挂了（路径写错、文件不在）就自动
> 露出底下的字，不会留一个裂开的图片图标。
> 卡片封面略有不同：它挂掉时会退回一张「图片」图标而不是标题首字，
> 那条兜底在 `bootDelegates()` 里（在 `app/boot.js`）—— `error` 事件不冒泡，
> 得在捕获阶段收。

**开发者模式的开关**（顶栏方块长按 3 秒才能看到那个齿轮，详见后面「开发者模式」一节）：

改的是 `data/site.js` 里的 `SITE.dev`：

```js
dev: true      // 改成 false → 长按彩蛋整个关掉，齿轮永远不出现
```


背景图、粒子、主题模式也在 `SITE` 里，下面几节（⑦⑧）单独说。

### ② 文章 `POSTS`

加一篇就是复制一整个 `{ ... }` 块，粘在下面，中间用逗号隔开：

```js
{
  id: 'my-post',                  // 网址里用，英文，别重复
  title: '文章标题',
  date: '2026-09-11',             // 必须 YYYY-MM-DD 格式
  tags: ['前端'],                 // 标签，点一下就能筛出同标签的文章
  cat: 'tech',                    // 可选，对应下面 ③ 里 CATEGORIES 的 key
  cover: './covers/my-post.png',  // 可选，卡片封面图。没有就删掉这行
  summary: '列表页显示的一句话摘要。',
  body: `
正文写在这里，支持 Markdown：

## 二级标题
### 三级标题

- 列表项
- 列表项

> 引用

**粗体**、\`行内代码\`、[链接](https://example.com)

\`\`\`js
console.log('代码块')
\`\`\`
`
}
```

> ⚠️ `body` 用的是**反引号**包起来的多行字符串。如果你正文里要写反引号（比如行内代码），
> 前面得加反斜杠转义：`\``。这是唯一的坑。

> 💡 `##` 标题会自动生成文章目录，代码块右上角会自动出现「复制」按钮。
> 这两样都不用你手动写。

### ③ 分类 `CATEGORIES`

文章的 `cat` 字段填这里的 `key`：

```js
const CATEGORIES = [
  { key: 'tech',  name: '技术手札', icon: 'tech',  desc: '代码与 Bug 的爱恨情仇' },
  { key: 'life',  name: '随笔杂谈', icon: 'life',  desc: '生活琐事与碎碎念' },
  // 想加就照格式往下写，注意每行末尾的逗号
]
```

- `icon` 是 `icons/` 文件夹里的**文件名**（写 `tech` 就是 `icons/tech.svg`），不是 emoji
- 文章 `cat` 填了这里没有的值，文章上照样显示，但点进分类页是空的
- 不想要哪个分类就从数组里删掉那行

> 💡 它管两件事：写文章时下拉框里的选项（`app/view-posts.js`），以及把文章上的
> `cat` 翻成中文名显示（`app/views.js` 的 `catName`）。分类页 `#/cat/<key>` 照常能用，
> **入口在文章列表里每篇文章的分类名上**，点一下就按分类筛。
>
> 首页原来那排「快捷导航」大图标卡已经删掉了（跟侧边栏重得太多），所以 `desc`
> 这个字段目前只有编辑表单在用，首页不再显示它。

### ④ 作品 `WORKS`

项目名、描述、技术标签、链接。

### ⑤ 下载 `FILES`

指向 `files/` 文件夹里你放的文件。详见 `files/把文件放这里.txt`。

**这个数组不用手写** —— 把文件丢进 `files/`，双击根目录的「更新下载列表.bat」，
清单自己就长出来了（原理见「下载清单」一节）。手写只在两种时候用得上：
要挂网盘外链，或者想给某个文件起个跟文件名不一样的显示名。

每条除了 `name` / `file` / `size` / `desc`，还有一个可选的 `folder` ——
**所在文件夹的名字，也就是 `files/` 下那个子文件夹**。留空时自动从 `file`
路径里读（`./files/plus/弹球.zip` → `plus`），所以多数时候不用写。

还有一条可选的 `time` —— **登记时间**，格式是定长的 `YYYY-MM-DD HH:MM`。
下载页的排序靠它，手写时可以整个不写（时间序里会沉到底下），脚本生成的条目都会带上。

下载页按 `folder` 分成两层：第一层列出所有文件夹（含「未分类」），点进去才看到
里面的文件，标题右边是面包屑 `文件下载 / plus`。同一层里可以在列表 / 网格
两种视图间切换，列表一页 10 条、网格一页 30 格；上传按钮右边还有一排排序开关，
按「◷ 时间」（最新登记的在前）或「A 首字母」（中文按拼音）排，选哪个记在浏览器里，
下次打开还是它。

> ⚠️ 文件夹列表是按**有哪些文件**算出来的，不是真去翻文件夹 ——
> 建个空文件夹、里面不放文件，页面上是不会出现的。

### ⑥ 网站导航 `SITES`

左侧导航里那一项「网站导航」（`#/sites`）的内容。一个分类一节，节里是若干网站：

```js
const SITES = [
  {
    key: 'dev',                 // 分类的英文标识，网站靠它归类
    name: '开发资源',
    icon: 'tech',               // 图标名，见下面
    desc: '天天要用的一堆',
    links: [
      { name: 'GitHub', url: 'https://github.com', desc: '代码托管' }
    ]
  }
]
```

`url` **不写协议也行**（`github.com` 会自动补成 `https://github.com`），
所有网站都是**新窗口打开**。

`icon` 只能填现成图标的名字（`data/icons.js` 里有的那些）—— 图标是提前打包好的，
加新图标要跑一次「icon更新.bat」。拿不准填什么就随便写，页面会兜底成 `compass`。

想加一个分类，就是复制上面那一整个 `{ ... }` 块，粘在下面，中间用逗号隔开：

```js
  {
    key: 'tool',
    name: '在线工具',
    icon: 'tool',
    desc: '不用装就能用',
    links: [
      { name: 'JSON 格式化', url: 'https://json.cn', desc: '粘上去就排版' },
      { name: '正则测试', url: 'https://regex101.com', desc: '' }
    ]
  },
```

> 📌 `key` 是**分类的身份证**，开发者模式里「给这个分类加网站」靠它认人，
> 所以改了 `name` 别顺手把 `key` 也改了。它只能是英文小写字母、数字和短横线。
>
> ⚠️ 两个分类别用同一个 `key`，会打架。

> 💡 懒得改文件？开发者模式开着的时候，每个分类头右边有
> 「+ 网站 / 编辑分类 / 删除分类」，每个网站右边有「改 / ×」，点着加就行。

### ⑦ 背景图（白天一张、夜里一张）

背景图是**整个网站**的 —— 铺满整个视口，跟着你滚动一直在底下，和你在哪个页面无关。
一张白天用、一张夜里用，切换深浅色的时候两张**交叉淡化**（不是「啪」地跳一下）。

现在用的是两张占位图：`bg.svg`（白天，蓝天渐变 + 云）和 `bg-night.svg`
（夜里，星空 + 月亮）。在 `SITE` 里控制：

```js
bgDay:   './bg.svg',        // 亮色模式看到的
bgNight: './bg-night.svg',  // 暗色模式看到的
bgVeil:  0.62,              // 遮罩浓度 0~1
```

**换成自己的照片：**

1. 挑一张白天的照片、一张夜景照片，放进这个文件夹
2. 改上面两行，比如 `bgDay: './bg-day.jpg'`、`bgNight: './bg-night.jpg'`
3. `bg.svg` 和 `bg-night.svg` 就可以删了

照片建议 **1920×1080 左右、每张压到 300KB 以内**，不然手机上加载会明显卡顿。
可以用 [squoosh.app](https://squoosh.app) 在线压，免费。

> 💡 两张图**构图尽量接近**（比如光源都在右上、地平线高度差不多）。
> 淡化的时候两张同时在画面上，构图差太多会看出「叠影」。

- 只想用一张图 → 两行写成同一个路径，夜里那张就等于没效果
- 不想要背景图 → 两行都写 `null`，只剩底色渐变

**`bgVeil` 是干什么的：**

背景图上面盖了一层遮罩，数值越大遮罩越浓、文字越清楚，但背景图也越淡。

- 字看不清 → 调大（`0.75`）
- 背景图太糊 → 调小（`0.4`）
- 不想要背景图 → 两个路径都写 `null`

> ⚠️ **别把 `bgVeil` 调到 0.3 以下** —— 照片细节一多，正文就会读得很累。
> 玻璃面板本身是半透明的（`--panel` 的 alpha 是 `.68`），底下有图的时候
> 对比度会下降。

> 💡 **面板发蓝怎么办？** 按顺序查这三件事：
>
> 1. **`--panel` / `--panel-soft` 的 alpha**。面板是半透明白，透出来的就是
>    你背景图的颜色。调高 alpha 更白、更不透明，或者把背景图换成浅色的。
> 2. **`--blur`**。模糊半径大，背景的颜色会被更多地搅进面板里。
>    但**别为了「不发蓝」把它压到 3px** —— 那样照片的细节原样透出来，
>    看着像隔着塑料膜，不像毛玻璃。现在 `12px`，霜的质感才对。
> 3. **最后确认 `backdrop-filter` 里没有 `saturate()`**。
>    它会把背后颜色的饱和度放大，蓝底会蓝得更厉害，白面板也救不回来。
>    全站已经清零，有断言盯着，别加回去。
>
> 还有一个**不要动**的地方：正文插图的阴影是单独写的，没走 `--panel-shadow`。
> 因为 `--panel-shadow` 第一层是白色外发光，套在照片上就是一圈光晕。

### ⑧ 背景粒子（栏背后那层特效）

背景图之上、面板之下飘着的那层小几何图形。**亮色和暗色是两套完全不同的形状**：

| | 形状 | 颜色 |
|---|---|---|
| 亮色 | 三角 / 碎片 / 菱形 / 六边形 / 方块 | 取自 `--reflection-1..7`（和首屏彩虹同一套色），半透明叠色 |
| 暗色 | 圆点 / 星星 | 冷白，加成混合（`lighter`），会缓慢明暗呼吸 |

在 `SITE` 里调：

```js
particles: {
  enabled: true,   // 不想要这层特效就写 false
  count: 80,       // 粒子个数。嫌闹腾就调到 30 左右
  speed: 0.5       // 漂浮速度，1 大约是它的两倍快
},
```

> 💡 粒子跑在 `<canvas>` 上，会跟着系统设置走 ——
> **开了「减少动态效果」（`prefers-reduced-motion`）就自动不启动**，
> 这是给晕动症用户的，别去掉这个判断。
>
> 换主题时粒子会**整体重建**（形状池和颜色都不一样），不是简单换个色。



#### 首屏的彩虹镀膜

首页大标题背后那层会变色的反光，是七种颜色各出两条色带叠出来的
（`--reflection-1` 到 `--reflection-7`，色带本身在 `--reflection-gradients` 里）。
每条色带的第二个 stop 故意和第一个错开一点，才有「镭射纸」那种会随角度变色的感觉；
只画一条的话就是七道死板的平行条纹。

| 变量 | 作用 |
|---|---|
| `--reflection-angle` | 色带角度，默认 `60deg`。**想改方向只动这一个值** |
| `--reflection-1` … `--reflection-7` | 七种颜色，括号里最后一个数是透明度 |
| `--reflection-gradients` | 那 14 条色带本身。**这个不要改**，改颜色就够了 |

`--reflection-gradients` 全站**只定义一次**（在 `:root`）。暗色模式下只覆盖
`--reflection-1` 到 `--reflection-7` 这七个颜色（换成冷白/浅蓝调），色带堆本身不重写 ——
因为色带里引用的是 `var(--reflection-N)`，改了颜色那边自动跟着变。

**不想要镀膜**：把 `--reflection-gradients` 设成 `none` 就行，
`.hero::after` 会自动变成一层空的东西。想整体删掉的话，连着 `.hero::after`
那条规则一起删。

> ⚠️ 但 `.hero` 上的 `isolation:isolate` **别顺手删掉**。那两个伪元素用的是负
> `z-index`（`::after` 是 `-2`、`::before` 是 `-1`），负层级要往哪儿钻取决于
> 最近的那个层叠上下文是谁 —— 不写 `isolation` 就得靠祖先元素碰巧合适，
> 以后随便改个 `transform` 或 `filter` 就可能让彩虹翻到白色光晕上面去，压到标题底下。
> `isolation` 把两个伪元素关在 `.hero` 里面，顺序就定死了。

### 换配色

配色全在 **`styles/variables.css`** 里 —— 其它样式文件里的颜色都走 `var()`，
改这一个文件就够。文件最上面是两块原始素材：

**天空蓝色阶**（`--sky-50` 最浅 → `--sky-700` 最深）是原始色板。
最深只到 `#2b87c4`，**整站没有深海军蓝**。

**黑**：`--ink` 是正文和标题色，`--ink-2` 是次要文字（偏冷的蓝灰，
不是纯黑，避免大片死黑）。黑色只用在文字上，用量克制。

> ⚠️ **`--ink-2` 从 `#55768c` 压深到了 `#47647a`，这是被可读性逼的。**
> 面板改成半透明之后，背景照片**最暗的地方**会透过面板垫在次要文字后面，
> 原来那档算下来只有 **3.61:1**，低于 WCAG AA 要的 4.5。
> 压深之后最坏情况是 **4.66:1**，过了。
>
> 色相没动，还是同一个蓝灰，只是亮了一档变暗。
> **想换回原来的观感就把这行改回 `#55768c`** —— 但那样照片暗部上的
> 次要文字（日期、摘要、说明文字）会偏吃力。

**语义变量**才是你真正要改的：

| 变量 | 作用 |
|---|---|
| `--bg` / `--bg-grad` | 页面底色（没背景图时看到的渐变） |
| `--text` / `--muted` | 正文色 / 次要文字色 |
| `--link` | 链接色 |
| `--panel` | 玻璃面板底色，**alpha 就是透明度**，想更透就调小。默认 `.68` |
| `--panel-soft` | 更透的一档（页眉、侧边栏、页脚、标签），`.58` |
| `--panel-strong` | 更实的一档（代码块、行内代码），`.86` |
| `--blur` | 毛玻璃模糊半径，默认 `12px`。**调大更朦胧，但也更容易发蓝**（见下） |
| `--rail-anim` | 侧边栏收展的时长 + 曲线，`.38s` + 会「弹一下」的那条贝塞尔 |
| `--panel-shadow` | 面板的立体感：白色外发光 + 阴影阶梯 |
| `--glass-bevel` | 三段式内嵌斜角：左上白边、右下暗边、内部白晕 |
| `--glass-sheen` | 面板表面那层白（玻璃中间比上下亮） |
| `--anim` | 全站统一缓动曲线 `cubic-bezier(.25,.46,.45,.94)` |
| `--radius` / `--radius-sm` | 圆角，`8px` / `6px` |
| `--accent` | 主色，只在导航选中态等小面积处露脸 |
| `--hero-scrim` | 首屏大标题背后的光晕 |

#### 玻璃材质是怎么回事

面板的「玻璃感」不是靠把背景糊掉糊出来的，是靠**边缘**骗出来的。四样东西：

1. **三段式内嵌斜角**（`--glass-bevel`）—— 左上 1px 白、右下 2px 暗、内部 20px 极淡白晕。
   这是让面板像「一块有厚度的玻璃」而不是「一张贴纸」的关键，比模糊本身重要得多。
2. **白色外发光**（`--panel-shadow` 的第一层）—— 是 `rgba(255,255,255,.40)`
   而不是深色投影。深色投影是「压在下面」，白发光是「浮在上面」，观感完全不同。
3. **表面白层**（`--glass-sheen`）—— 两层白渐变叠出「中间比上下亮」的玻璃弧面感。
4. **模糊** —— 现在 `12px`。面板本身够白了（`.68`），背后再糊狠一点，
   「霜」的质感才出得来。

暗色模式这套是**换过的**，不是同一份：发光换成两层黑投影，表面白层从上下渐变
换成 135° 斜向渐变。三处声明里的值不一样，别以为是复制粘贴漏改了。

交互反馈也统一了：悬停上浮 `2px`、按下 `scale(.995)` 并轻微变透、
所有过渡都是 `.3s` + `--anim` 那条曲线。

想整套关掉玻璃质感、回到扁平：把 `--panel-shadow` 改成一个普通的
`0 2px 8px rgba(23,25,28,.10)`，`--glass-bevel` 和 `--glass-sheen` 设成 `none`。

> ⚠️ 改 `--panel-shadow` 时**保持第一层是白色外发光**。删掉它卡片会立刻「塌」下去，
> 整个页面变得很平。

> 💡 **`--panel` 的 alpha 就是「透不透」。**
> 现在是 `.68` —— 照片能透出来，字还压得住，这才叫毛玻璃。
> 之前是 `.88`，那基本等于一块白板，看不出背后有图。
>
> **字为什么还压得住**：靠的是外面那层遮罩（`--bg-veil`，默认 `.62`）。
> 背景先被 62% 的白洗过一遍，面板再叠 `.68` 的白，落到正文上的对比度
> 跟纯白底差不多（实测最暗处 13:1，最亮处 17:1）。
> **这两层是一套，改一个要回头看另一个。**
>
> ⚠️ **别再把 alpha 调回 `.85` 以上** —— 那就退回「一块白板」了，
> 用户提的「你没做毛玻璃」说的就是这个。
> 想更透可以往 `.6` 试，但调完一定要确认 `--muted` 那档次要文字还看得清
> （它是最先掉下去的，见下面「次要文字」那条）。

`html[data-theme="dark"]` 那块是暗色模式的对应值，改配色时**两边都要改**，
不然切到暗色会瞎。

#### 关于链接色

`--link` 现在是 `#146eb0` —— 一档中等亮度的蓝。**这是被可读性逼出来的**：
真正的浅蓝（比如 `--sky-300` 的 `#b6dff8`）在白底上对比度只有 1.9:1，
远低于 WCAG 要求的 4.5:1，当链接色会看不清。

如果你想要更浅的观感，有两个选择：

1. **链接改成黑字 + 浅蓝下划线**（最贴合「浅蓝白黑」）：
   ```css
   --link:var(--ink);
   ```
   下划线本来就是浅蓝的，链接照样认得出来。

2. **换个更浅的蓝**，但要知道自己在牺牲可读性：
   ```css
   --link:#2b87c4;   /* 对比度约 3.7:1，大字号没问题，正文偏吃力 */
   ```

同理，主按钮是**浅蓝底 + 黑字**，不是浅蓝底 + 白字 —— 后者对比度不够会糊。

#### 夜间模式 / 暗色模式

侧边栏最底下那个按钮就是主题开关，**点一下换一种**，三种循环：

| 按钮长这样 | 意思 |
|---|---|
| 🌗 跟随时间 | 按当前时间自动决定（默认就是这个） |
| ☀️ 亮色主题 | 锁死亮色 |
| 🌙 暗色主题 | 锁死暗色 |

选过之后就记住了，下次打开还是你选的那个；没选过就是「跟随时间」。

**夜间时段**在 `SITE` 里改：

```js
nightFrom: 18,   // 18 点之后自动切暗色
nightTo: 6,      // 早上 6 点之后自动切回亮色
```

这是个**跨午夜**的区间（18 点 → 次日 6 点）。代码会自己判断该按跨午夜还是不跨
来算，所以你写成 `nightFrom: 9, nightTo: 17`（白天用暗色）也能正常工作。

判断每秒都在跑（搭在时钟上），所以**开着页面跨过 18 点会自己变暗**，不用刷新。

**彻底不要暗色**：把 `SITE` 里这行改成 `false`，会锁死亮色并把那个按钮藏起来。

```js
allowDark: true,   // 改 false → 只剩亮色，主题按钮消失
```

> ⚠️ `--bg-veil`（背景图遮罩浓度）**没有**在暗色块里单独声明，两个主题共用
> `SITE.bgVeil` 一个值。原因写在代码注释里：它被 `bootBackground()` 写成了
> `<html>` 的行内样式，行内样式压过一切选择器 —— 在暗色块里再写一遍是**死代码**，
> 改了会发现没反应。要调就在 `SITE.bgVeil` 调。

> 注：老浏览器不支持 `backdrop-filter`，毛玻璃会失效。
> 我在 `@supports not (...)` 里做了兜底 —— 那种浏览器上面板会自动变实，
> 保证字能看清，不会出现「半透明面板贴着花背景」的惨状。

### 首页那一整块面板

首页不是「一块打招呼的板子 + 下面几块」，而是**一整个 `.home-panel`**，
里面从上到下依次是：

| 区块 | 类名 | 内容 |
|---|---|---|
| 横幅 | `.home-banner` | 居中那行大字（`SITE.banner`），背后有光晕 |
| 关于我 | `.home-about` | 头像（`.ha-avatar`）+ 招呼语和自我介绍 + 右侧签名列 |
| 联系方式横条 | `.home-contact` | 一条窄玻璃条，横在中间当分隔 |
| 最新动态 / 作品 | `section` + `.grid` | 两节卡片，节与节之间一条细线断开 |

前三块的文字内容全在 `SITE` 里（见 ① 站点信息）。

这么写是为了对齐参考站的首屏 —— 那边就是一整块大玻璃里装着全部内容。
以前 hero 是单独浮在面板外面的，会**压掉下面「最新动态」的半截**，这个已经修掉了。

> 横幅那个 div 上**同时挂着 `.hero` 和 `.home-banner`**，是故意的：留着 `.hero`
> 是为了那团白色光晕（`.hero::before`），字号排版交给 `.home-banner` 自己接管。
> 头图背后的彩色是**面板那层彩虹**透上来的，不在这儿单独铺了（见「彩虹镀膜」一节），
> 铺两道会叠得更重，而且面板那道是视口锚定的，自己再来一道就不连续了。
>
> 历史：`.hero::after` 以前确实挂着一道彩虹，后来挪走了 —— 所以你在旧笔记里
> 看到 `.hero::after` 的话，那已经是过去式了。

### 头像：点一下翻面

首页那个头像圈是枚「硬币」，**点一下绕竖轴翻 180°**，正面是 `SITE.avatar`，
背面是 `SITE.avatarBack`（不填就退回用 `avatar`，翻过去还是同一张，看着像卡住了）。

结构上套了两层，别拆：

```
.ha-avatar      ← 容器，负责 perspective（3D 景深）和点击热区
  └ .ha-flip    ← 硬币本体，负责 transform-style: preserve-3d 和那个 rotateY
      ├ .ha-face            正面
      └ .ha-face.ha-back    背面，预先 rotateY(180deg) 转到对面
```

两个 `backface-visibility:hidden` 是必须的 —— 少了它，转过去背对自己的那一面
会透过来，看到反着的字。

> ⚠️ **`perspective` 和 `preserve-3d` 一个都不能少。** 少了 `perspective`，
> `rotateY` 会被当成平面压扁，转起来是「缩成一条线」而不是「翻过去」；
> 少了 `preserve-3d`，两个面各自被压平，背面那个会一直正着贴在同一层上。
>
> ⚠️ **圆的 `overflow:hidden` 从 `.ha-avatar` 挪到了 `.ha-face` 上**，
> 容器上留着的话，转动的面会在半路被切掉一条边。

翻面本身只是加/去掉 `.is-flipped`，点击由 `boot.js` 的 `bootAvatarFlip()` 委托处理
（视图是整块 `innerHTML` 换掉的，绑在元素上的监听活不过一次重绘）。

改的时候注意两件事：

- **`.home-panel` 的 `background` 拆成了 `background-color` + `background-image` 两条写。**
  不能图省事写成 `background:` 简写 —— 简写会把表面那层白（`--glass-sheen`）冲掉，
  而且 hover 里再写一次简写也会。这个坑在 `.card` 上踩过一次了。
- **方格纹理只铺在 `.card` 上，大面板、顶栏、侧边栏都是干净的一片。**
  参考站就是这样：只有主内容里那些小格子有网格，外围的大板子没有。
  以前大面板上也铺过，看着像整张稿纸，已经去掉了 —— 别再往回加。
- **面板上的 `overflow:hidden` 别删。** hero 那两个装饰伪元素（光晕、彩虹）
  是负 `inset` 的，靠这个把光晕裁在面板里面，删了会糊到面板外面去。

### 关掉卡片的方格纸纹理

卡片上那层浅蓝方格纸是 `--grid-line` 画出来的。**全站只有卡片有这层纹理**
（大面板、顶栏、侧边栏都是干净的），想关掉：

```css
:root{ --grid-line:transparent }
```

⚠️ 颜色变量有**三份** —— `:root`（亮色）、`html[data-theme="dark"]`、
`@media (prefers-color-scheme:dark)`。只改一份的话，切主题的时候另外一半还是老样子。
尺寸变量（`--rail` 这些）不是颜色，只有 `:root` 一份，别去找。

### 侧边栏

侧边栏是浮在顶栏下面的圆角面板，**平时只露图标，点右上角那个 `«` 展开**才显示文字。
展开状态会记住，刷新后还在。

| 变量 | 作用 |
|---|---|
| `--rail` | **当前**宽度（不收展时别直接改这个，改下面两个） |
| `--rail-open` | 展开后的宽度，默认 `208px` |
| `--rail-gap` | 离窗口左边缘、下边缘、以及离顶栏的缝，默认 `10px` |
| `--edge` | **顶栏**离窗口上/左/右的缝，默认 `10px`（和侧边栏那块板对齐） |
| `--shell` | 从上面两个算出来的让位宽度，`body` 用它做 `padding-left` |
| `--rail-anim` | 收展用的时长 + 曲线，`.38s` + 会「弹一下」的那条贝塞尔 |

收/展只改 `--rail` 一个变量（规则是 `html[data-rail="open"]`），栏宽和正文让位
是一起动的。**`--shell` 别手动改** —— 它是 `calc(var(--rail) + var(--rail-gap) * 2)`，
改了会和实际栏宽对不上。

> ⚠️ **栏宽、`body` 让位、顶栏偏移、文字展开，四处必须共用 `--rail-anim`。**
> 这是踩过的坑：动画曲线只要有一处不一样，中途就会错位 ——
> 正文已经滑到位了顶栏还在慢慢挪，或者文字已经淡入但格子还没撑开。
> 觉得「展开的时候有点晃」多半就是这里漏了一处。有断言盯着，改的时候别绕过变量。

导航图标在整条侧边栏里是 **`justify-content:space-evenly` 均匀铺开**的
（和参考站一样）。**别改回靠 `gap` 挤在顶上 + 底下塞个撑杆** ——
那样中间会空出一大块白的，就是之前「有一块在视觉上是空白的」那个问题。

### 顶栏

**顶栏和侧边栏、主面板是同一块材质** —— 浮起的圆角玻璃，四周留缝，有自己的阴影和
斜角。它**不贴顶**，离窗口上/左/右各留 `--edge`（默认 `10px`），左边缘和侧边栏那块
板在同一条竖线上。

`header` 上一句负 `margin-left` 抵消 `body` 的左内边距、再退回 `--edge`，所以窗口
宽度减去两倍的 `--edge` 正好是它的宽。

**`.bar` 现在是铺满整条顶栏的**：品牌贴在左边缘（离面板 `22px`），搜索和状态贴在
右边缘，时钟在剩下的空档里靠 `margin:0 auto` 居中。

> 以前 `.bar` 上卡着 `max-width: calc(var(--maxw) + var(--shell))`，还额外给了一份
> `padding-left: calc(22px + var(--shell))`，为的是让品牌和搜索**跟下面正文的左右边缘对齐**。
> 但 `--maxw` 只有 `1080px`，窗口一宽这一条就被居中收窄，品牌被顶到离窗口左边两百多
> 像素的地方，顶栏左边空出一大片。现在宽度放开了。
>
> 副作用：搜索框和状态跟着往右挪了约 110px（还是右对齐，元素本身一个字没改）。
> 想改回「跟正文对齐」就把那两行加回去。

> ⚠️ **`body` 上那句 `padding-top:var(--edge)` 别删。**
> 顶栏是 `sticky` 且 `top:var(--edge)`，而 `top` **不会改变它在正常流里的位置** ——
> 滚动位置为 0 时它会被「按下去」10px，可它占的那块地方还留在原地，
> 于是正好压住下面正文的脑袋。`body` 留出同样宽的一条上内边距，它一开始就待在该待的地方。

侧边栏的起始高度用的是 `--bar-h`（顶栏高度，由 `syncBarH()` 量出实际值写进变量），
所以它从「`--edge` + 顶栏高度 + `--rail-gap`」开始算。你改 `.bar` 的 `padding` 之后
不用手动同步这个值。

窄屏（≤ 760px）时侧边栏自动变成贴边的底部横条，`--rail` / `--rail-gap` 归零
（`--edge` 不归零，顶栏那道缝还得留着，只是收窄到 `8px`），展开按钮和文字都藏起来。

> ⚠️ **窄屏那段媒体查询里，选择器必须写 `:root`，不能写 `html`。**
> `--rail` / `--rail-gap` / `--edge` 是在 `variables.css` 的 `:root` 里声明的，
> `:root` 是伪类、优先级 `(0,1,0)`，而 `html` 只是类型选择器 `(0,0,1)` ——
> 光写 `html` 根本盖不住，手机上会继续用桌面那份 `72px` 栏宽和 `92px` 让位，
> 页面上能看见左边空出一大条。**这个坑真踩过**，写的时候照抄
> `:root,:root[data-rail="open"]{ ... }` 那一行。

侧边栏里有哪几项由 `NAV` 决定：

```js
const NAV = [
  { hash: '#/', label: '首页', icon: 'home' },
  // icon 是平时露出来的图标（名字对应 icons/ 里的文件，见「图标」一节），
  // label 展开后显示在旁边，同时兼作悬停提示和无障碍朗读
]
```

### 彩虹镀膜

全站玻璃板上那层会随滚动「流过」的淡彩，是 `styles/rainbow.css` 里一条规则给的：

```css
header::after,
#rail::after,
.home-panel::after,
.card::after,                     /* 卡片 */
.home-contact::after,             /* 首页那条「联系我」 */
.toc::after, .article .body::after,  /* 文章目录 + 正文那块 */
footer::after{
  background-image: var(--reflection-gradients);
  background-attachment: fixed;   /* ← 关键 */
  opacity: calc(var(--rainbow-alpha) * var(--rb-scale, 1));
}
```

**哪几块镀、哪几块不镀**，原则是「看着像一块玻璃板的都镀」：

| 镀 | 顶栏、侧边栏、首页大面板、页脚整条、文章目录、正文那块 |
|---|---|
| **打折**镀 | 文章卡、分类卡、首页「联系我」那条（见下面 `--rb-scale`） |
| **不**镀 | `.chip` 标签、`.icon-btn`、搜索框、`.ha-social` 胶囊、`.copy-btn`、`.modal-box` |

不镀的那些读起来是「控件」不是「玻璃板」，镀了会像一个个亮着的小灯；
弹窗浮在遮罩上面，属于另一个层级，跟着页面一起反光也怪。

**为什么是 `background-attachment:fixed`**：它让所有板子取样的是**同一个视口坐标系**
的背景，于是整页彩虹是连着的 —— 一块板子上被切掉的那段，在隔壁那块上接着。
参考站也是这个思路（它是一片 `position:fixed` 的彩虹层，各块板子用 `clip-path`
开一扇窗），但开窗得拿 JS 量位置、还得跟着滚动和收展实时更新；`fixed` 零 JS 就做到了。

> ⚠️ **别改成默认的 `scroll`。** 那样每块板子都从自己的左上角重新数一遍色带，
> 各画各的，就变成「一块一块不一样的彩虹」了。
>
> ⚠️ **别再用 `closest-side` 的椭圆 mask 收边。** 这个是真踩过：顶栏是个又扁又长的
> 盒子，椭圆会被拉得横贯整条，中间那点透明区根本盖不住，整条顶栏会变成一面彩虹旗。
> 现在不收形状，靠颜色本身的透明度保证不刺眼。

调浓淡改 `:root` 里那一个值就行：

```css
:root{ --rainbow-alpha: 1 }   /* 调小就淡，0 就是彻底关掉 */
```

#### `--rb-scale`：叠着的板子要打折

卡片是**浮在**首页大面板上面的，而卡面是半透明的（`--panel` 是 60% 实心），
等于白捡了四成父级那条彩虹。不减一份的话，卡片会比周围的面板亮一截，
正好又变成「一块一块的」。所以：

```css
.home-panel .card,
.home-contact{ --rb-scale: .55 }   /* 折扣约等于「1 − 卡面不透明度」 */
```

`.card` 只在**首页大面板里**才是叠着的，别的页（`#/posts`、`#/works`…）它直接躺在
页面背景上、没有父级镀膜可透，所以用后代选择器挑，别一刀切写 `.card`。

#### 颜色

七种颜色是 `--reflection-1` 到 `--reflection-7`（配合 `--reflection-angle` 控制方向）。
**浅色主题那份是特意调过的**，别照抄参考站的原色：

> 参考站那套是 `rgba(216,15,15,.17)` 一类的正红正绿正蓝，在它那种**深色**玻璃上刚好；
> 搬到本站这种接近白的浅色玻璃上，近白的底子会把饱和度整个顶出来，
> 七道色带各走各的，看着像一面脏兮兮的彩旗。所以浅色这份统一往本站的天蓝偏、
> 降饱和、一档档压淡（`.30` 走到 `.09`），读起来是「一道冷色反光」而不是「七种颜色」。
> 最后两档暖色压得最狠，而且特意往**粉**里偏、不往黄里偏 —— 偏黄落在白玻璃上会读成土色。

**暗色那份压得更狠（大约只有浅色的一半）**，这不是随手写的，是数学：

> 浅色面板本身就接近全白，叠一层天蓝是**压暗**它，百分比变化很小；
> 暗色面板接近全黑，同一层天蓝是**提亮**它几十个百分点 —— 同样的 alpha，
> 暗色这边看着要亮好几倍。早先顶栏上那条明显的灰白「污渍」就是这么来的：
> 一栏亮、满页不亮，看着像脏了一块，而不是一层反光。
>
> 暗色那份在 `html[data-theme="dark"]` 和 `@media (prefers-color-scheme:dark)` 里
> **各写了一份、内容一模一样**，改的时候两份都要动 —— 加上 `:root` 里那份浅色的，
> 一共三处。

#### 两个必须一起给的东西

- **`isolation:isolate`** —— 把负 `z-index` 的伪元素关在自己的层叠上下文里。
  不写它会一路钻到页面根背景底下，整块直接看不见。
- **`position:relative`** —— `inset:0` 得有个定位祖先，才量得准是「自己这块板」。
  不写会退到初始包含块（视口）上去；镀膜本身是 `fixed` 的画出来差不多，
  但 `border-radius:inherit` 的四个角会落到错的地方。

两样都在 `rainbow.css` 里统一给，加新板子的时候记得往那两个列表里补一行。

### 顶栏方块：长按 3 秒的彩蛋

顶栏左上角那个方块（`#brandMark`）有三副面孔：

- **短按** —— 回首页（它本来就是个首页入口）
- **长按 3 秒** —— 方块抖起来、外面一圈进度环走满，然后**炸开**，
  露出一个齿轮按钮
- **右键**（只在解锁之后）—— 恢复成普通方块，见下面「怎么退出去」

齿轮按钮就是开发者模式的开关。

触发时长有**两处**，改一个必须改另一个：

| 在哪儿 | 是什么 |
|---|---|
| `app/dev.js` 的 `bootSecret()` | `const HOLD = 3000` |
| `styles/aero.css` | `.mark.is-press .mark-ring circle` 的 `transition: stroke-dashoffset 3s` |

解锁状态记在 `localStorage` 的 `kili.dev`：**按过一次就一直解锁**，
下次打开直接显示齿轮按钮，不用每次重按。

#### 怎么退出去

三条路，**后两条走的是同一个 `devRelock()`**，所以不会出现两边状态对不上的情况：

| 怎么点 | 会怎样 |
|---|---|
| **再点一下齿轮** | 只关掉开发者模式 —— 控件收回去，齿轮还留着，随时能再点开 |
| **右键点一下方块** | 方块恢复原样、齿轮收起来、开发者模式一起关掉 |
| 工具条上的「退出」 | 同上 |

后两条还会顺手把 `kili.dev` 也清掉 —— **下次想再进，得重新长按 3 秒**。

> ⚠️ **方块里不能整块 `innerHTML` 覆盖。** 里面有占位字/图片（`#markFace`）、
> 进度环、爆炸碎片层、齿轮按钮四样东西。`paintMark()` 只写 `#markFace` 那一小块，
> 写成 `#brandMark` 的话，长按彩蛋会连同按钮一起被冲掉。
>
> ⚠️ **`.mark` 上不能有 `overflow:hidden`。** 爆炸碎片要飞出方块外面。
> 图片的圆角改由 `.mark-face` 自己裁。
>
> ⚠️ **齿轮按钮那两行 `position:relative;z-index:1` 不能省。** 齿轮和方块脸
> （`.mark-face`）叠在同一个网格格里，而 `.is-dev` 给方块脸加了 `opacity:0` ——
> 按 CSS 的规定，`opacity` 小于 1 又不是定位元素的东西，要**当成 `z-index:0`
> 的定位元素来画**，于是它反而压到了没定位的齿轮上面，把点击全吃掉。
> 症状很有迷惑性：齿轮刚炸出来那 1.5 秒里点得动（那时 `.mark-dev` 自己也带着
> 动画，两者同级，文档顺序在后的按钮赢），等爆炸动画一撤就再也点不开了。
> 所以 `.mark.is-dev .mark-face` 除了 `opacity:0` 还得给 `pointer-events:none`。

### 开发者模式

**先说它不是什么 —— 这不是安全机制，只是一道「别让人手滑点进来」的 UI 锁。**

长按顶栏方块 3 秒 → 炸出齿轮 → **点一下齿轮就是开关**：

- **打开** —— 页面上直接长出「写新文章」「编辑」「删除」这些按钮，图片变得可以点，
  右下角浮出一条工具条
- **再点一下**（或者点工具条上的「退出」）—— 全部收回去，页面回到正常样子

**没有密码了。** 之前那版点开齿轮要输账号密码，可密码只能明文写在 `data/site.js` 里、
跟着网站一起部署上去，谁按个 F12 都看得见 —— **挡不住任何人，却挡得住自己**。
这是零依赖的静态站（双击 `index.html` 就能开），**压根没有「服务器」这一环**，
验证只能发生在访问者自己的浏览器里，也就必然能被绕过。真要保护什么，得放到后端去做。

所以：**别把任何要紧的东西放在这个开关后面。** 它改的是你自己浏览器里看到的内容
（换图、写文章、加作品、传文件、加网站导航），改了也只存在你这台机器上。

想彻底关掉这个入口，把 `data/site.js` 里的 `dev` 写成 `false` ——
长按彩蛋整个失效，齿轮永远不出现。

#### 开关记在哪儿

| 键 | 意思 |
|---|---|
| `kili.dev` | 齿轮露出来了没有（长按解锁过一次就一直记着） |
| `kili.devmode` | 当前是不是开着 |

页面根元素（`<html>`）上挂一个 `dev-on` 类，**所有编辑控件靠它显隐**。
所以开关一下只翻一个类名、不重画页面 —— 滚动位置、正打到一半的输入框、
展开着的详情都不会被重置。

> ⚠️ 那些编辑控件是**照常渲染出来、带 `.dev-only`** 的，靠 CSS 一条规则藏住：
> `html:not(.dev-on) .dev-only{display:none !important}`。
> 写法是「只在**没开**的时候藏」，不是「开的时候显示」—— 因为同一批元素上还挂着
> `.dev-btn`（`inline-flex`）/ `.dev-row-act`（`flex`）各自的 `display`，
> 用一条规则去「显示」它们，要么压扁布局，要么得用 `display:revert` ——
> 而 `revert` 会退到**浏览器默认样式**、把作者样式一起丢掉，横排的按钮会竖起来。

> ⚠️ **小窗口和那条浮动工具条都挂在 `<body>` 下，不能放进 `main`。**
> `main` 上有悬停的 `transform`（见后面「三栏的悬停反馈」），而 `transform`
> 会成为 `position:fixed` 的**包含块** —— 放进去浮层会被困在 `main` 里，定位全乱。
> 以后再加浮层，也请挂在 `main` 外面。

#### 各页面分别能改什么

编辑都是**就地**的：点哪个按钮，表单就在哪儿展开，保存后页面当场重画。

| 页面 | 开着的时候多出什么 |
|---|---|
| **文章列表** `#/posts` | 顶部「+ 写新文章」；每张卡片右上角浮出「编辑 / 删除」 |
| **文章详情** `#/post/<id>` | 标题旁「编辑」；页面末端「删除这篇文章」 |
| **文章编辑页** `#/edit/new`、`#/edit/<id>` | 整页表单：标题 / 日期 / 分类 / 标签 / 封面 / 摘要 / 正文，正文下面是**实时预览** |
| **网站导航** `#/sites` | 每个分类「+ 网站 / 编辑 / 删除」；每个网站条目「编辑 / 删除」 |
| **作品** `#/works` | 顶部「+ 添加作品」；每张卡片「编辑 / 删除」，表单在卡片下面展开 |
| **下载** `#/downloads` | 顶部「+ 上传文件」（**常驻，不进开发者模式也有**）；每条文件「编辑 / 删除」，走小窗口 |

「写新文章」点下去会**跳到一个空文章页**（`#/edit/new`），不是弹窗 ——
写文章要一大片地方，塞进小窗口里光文本框就剩两行高。

**开发者模式没开时进 `#/edit/...` 会被拦下**，只显示一句提示。

> ⚠️ 编辑器一保存就回详情页。**没保存就离开会丢**，没有草稿箱。

#### 换图

开发者模式开着时，**页面上任何一张图都能点**：鼠标移上去会描一圈蓝边，
点一下弹出小窗口（预览现在这张 + 选新图 → **裁剪** → 还原）。

底下的机制是**两条通道**：

**① 站点图片位**（顶栏方块 / 头像正反面 / 白天夜间背景）
走 `kili.img.<字段>`，读的时候统一走 `siteImg('字段名')`（在 `app/util.js` 里）：

| 字段 | 是什么 |
|---|---|
| `markImg` | 顶栏左上角那个方块 |
| `avatar` | 首页头像（正面） |
| `avatarBack` | 首页头像（翻面） |
| `bgDay` | 白天背景图 |
| `bgNight` | 夜间背景图 |

背景图**不是 `<img>`**（它是 CSS 变量画的），点不到，所以这五张在右下角工具条的
「站点图片」按钮里列出来换 —— **选完图会走和页面上一样的裁剪那一步**，裁完立刻
生效，「还原」退回 `data/site.js` 里那张。

裁剪框的比例按每张图在页面上的样子来（`slotRatio()`）：

| 图片位 | 框的比例 | 为什么是这个 |
|---|---|---|
| `markImg` | 1:1 | 方块是 42×42，图在里面 `object-fit:cover` |
| `avatar` / `avatarBack` | 1:1 | 头像是 172×172，同样 cover；而且**显示出来是圆的**，所以框里画了一圈圆形遮罩 —— 四个角是真的会被切掉 |
| `bgDay` / `bgNight` | 当前窗口比例 | 背景铺满整屏（`.bg-layer` 是 `position:fixed;inset:0` + `background-size:cover`）。窗口比例一变它还会自己再裁一点，这里定下的只是「现在这一屏」 |

> ⚠️ 源图会先缩到各自 max 的**两倍**（封顶 2560）再进裁剪 —— 裁的是其中一块，
> 源太小一放大就糊。**真存下来的仍按各自的 max 封顶**（方块/头像 512、背景 1920），
> 所以并没有多占 `localStorage`。

**② 其余所有图**（文章封面、正文插图、以后新增的）
走一张**替换表** `kili.imgmap`：`{ 原始src: dataURI }`。
页面每次重画后扫一遍 `#view img`，命中就换掉（`applyImgMap()`，在 `paintView()` 末尾调）。

> 📌 为什么不在文章正文里回写 data URI —— 正文是给人读的 Markdown，
> 塞进几百 KB 的 base64 就没法看了。`imgmap` 是「你眼前显示成什么样」的覆盖层，
> 和开发者模式其它改动一个性质。

> ⚠️ 键是**图片原本的地址**（记在 `data-orig` 上），不然换过一次就认不出自己是谁了。
> 想永久换掉本地的相对路径图（比如 `./photo/a.jpg`），最省事的办法是直接拿新图
> 覆盖磁盘上那个文件。

**卡片封面是个特例。** `data/posts.js` 里没填 `cover` 的文章，渲染出来的是**占位块**
（浅蓝渐变 + 标题首字），**里面根本没有 `<img>`** —— 按上面那条路它应该点不到。
所以封面另外带一个 `data-cover-key`（`app/util.js` 的 `coverKey()`）：填了 `cover`
就是那个地址本身，没填就临时编一个 `#cover:<文章id>`。`#` 开头的键不可能是合法路径，
不会和真地址撞上（这也意味着**这个键不是真文件，别照着它去找图**）。

点图片换图的代码因此是两段：先认 `<img>`，再认 `.cover[data-cover-key]`。
只认前者的话，点没配封面的卡片等于什么都没发生（详见下面「捕获阶段」那条）。

**选完图之后还有一步裁剪**（`app/dev.js` 的 `openCropSheet()`）。不直接存，
先弹一个框让你看清「页面上会显示成什么样」：**框的比例就是被点那块的显示比例**
（卡片封面是 `16/9`，正文插图是它自己的比例，站点图片位见上面那张表），
拖动图片挪位置、滚轮或底下那条滑块缩放，点「就用这一块」才真的存下去。

> 💡 初始状态刻意做成「刚好铺满框 + 居中」，也就是 `object-fit:cover` 的默认表现 ——
> 不拖不缩直接确定，得到的正是浏览器本来会显示的那一块，等于没裁。

> ⚠️ 换算里最容易错的是坐标反算（图片偏移是负的，取负号才是原图上的起始坐标），
> 所以它单独抽成了 `clampCrop()` / `cropRect()` 两个**纯函数**，不碰 DOM ——
> 这样能脱离浏览器单独验算：拿「原图尺寸 × 框尺寸 × 缩放倍数 × 拖到哪个角」
> 组合出 144 组摆位，裁出来的那块都必须整个落在原图范围内。改摆图规则的话，
> 这组验算会先红。

> ⚠️ 导出宽度封顶 **1600px**（和 `readImageFile()` 一个尺度，省 `localStorage`）。
> 放大之后只裁小小一块的话，输出也跟着变小 —— 那是正常的，不是 bug。

> ⚠️ 浏览器给每个站点的 `localStorage` 只有 **5MB 左右**，图和文件很容易占满。
> 存不下的时候会弹提示 —— 换小点的东西，或者先把别的「还原」掉。
> 上传的图统一转成 JPEG，代价是**带透明通道的图会被填成黑底**。

#### 文章 / 作品 / 文件 / 网站

这四样能新建、改、删，改完页面立刻重画。

**机制和换图是同一个套路**：默认数据还是 `data/*.js` 里那些，开发者模式里的改动
另存一份在 `localStorage`，读的时候叠上去。合并逻辑在 `app/util.js`：

| 键 | 存什么 |
|---|---|
| `kili.posts` / `kili.works` / `kili.files` / `kili.sites` | `{ added:[], updated:{}, deleted:[] }` |
| `kili.file.<显示名>` | 上传的文件本体（data: URI） |

- `added` —— 你自己新建的条目（整个对象）
- `updated` —— 对已有条目的字段覆盖，主键是文章的 `id`、作品和文件的 `name`、网站的 `key`
- `deleted` —— 被删掉的条目的主键

读的时候一律走 **`mergedPosts()` / `mergedWorks()` / `mergedFiles()` / `mergedSites()`**
（都在 `app/util.js` 里），别直接读 `POSTS` / `WORKS` / `FILES` / `SITES` ——
读了就绕过开发者模式，在页面里改的东西看不出来。
`app/view-home.js` / `app/view-posts.js` / `app/view-others.js` 里所有渲染函数
用的都是合并后的结果。

> ⚠️ **来自 `data/*.js` 的条目只能「改」和「软删除」**（标记一下、不再显示），
> 没法从 `.js` 文件里真正抹掉 —— 浏览器写不了磁盘上的文件。
> 列表里那条小标签标的就是这个：**「来自 data/」** 的删不掉本体，
> **「自己加的」**才整个存在 `localStorage` 里、能真删掉。
> 删除确认框也会按情况提醒你。

所以「永久生效」的路子还是老一套：在页面里改好、看着满意了，
**自己把结果抄进 `data/*.js` 里再重新部署** —— 开发者模式只是个改起来方便的草稿台。

**文件页有两条路**：只填路径（文件还得自己放进 `files/` 文件夹），
或者点「上传文件本体」把文件读成 `data: URI` 存进 `localStorage` —— 后者连
文件本身都不用放进项目里。上传了本体的条目，下载链接会自动指向存下来的那份。

**新建条目时，除了说明和文件夹，别的都不用填**：选完文件，显示名自动取文件名
去掉扩展名（`弹球.zip` → `弹球`，见 `app/util.js` 的 `stemOf()`），大小自动算，
路径跟着「文件夹 + 文件名」实时拼出来。路径和大小那两栏在新建态是 `readonly` 的
（虚线下划线、颜色压暗），因为它们是从别处推出来的，手动改只会跟实际对不上。

小窗口里那栏「文件夹」是个**下拉**，列出现有的所有文件夹，另加「未分类」和
「＋ 新建文件夹…」—— 选最后一项，旁边会冒出一个输入框让你现场起名。它决定
这个条目归到下载页的哪一组，规则是：

- 选了文件夹 → 路径按 `./files/<文件夹>/<文件名>` 拼出来
- 反过来也行：自己填了路径，文件夹就从路径里读
- 两个字段最后都会写进条目，下载页靠 `app/util.js` 的 `folderOf()` 分组

编辑已有条目时，路径和大小两栏是可改的（要挂网盘外链就得改路径），保存时
也**不会**动 `time` —— 只有新建才盖登记时间，编辑一律保留原来那个，
不然改一下说明就跳到排序最前面了。

> ⚠️ 上传走的是 data: URI，二进制转 base64 会胖约 1/3，几 MB 的文件很容易吃满配额。
> 大文件建议还是放进 `files/` 文件夹、只填路径。

> ⚠️ **上传不等于发布。** 下载页那个「+ 上传文件」按钮是**常驻**的（谁都能点），
> 但它只是把文件读进**访问者自己那台电脑的浏览器**里 —— 换台电脑、清一次浏览器
> 数据就没了。想让所有人都能下载，文件必须真的放进 `files/` 文件夹再重新部署。

**文章编辑器**里**没有「ID」这一栏** —— 主键由标题自动推出来（`makePostId()`），
已有的文章 ID 定死不动（保存时不会动它，老链接才不会断）。中文标题会被压成
`post-xxxxx` 这种带时间戳的 id：中文在 ID 规则里会被整段压掉，不退化成时间戳的话，
两篇中文标题会撞成同一个 id，路由和存储全串台。重名时自动补 `-2`、`-3`。

正文支持的那套 Markdown 就是 `app/util.js` 里 `md()` 认的那些：
标题、列表、引用、粗体、行内代码、代码块。摘要留空的话会自动从正文里抓头 60 个字。

### 图标（`icons/` 文件夹 + `data/icons.js`）

**先说结论：换图标之后要双击一次「icon更新.bat」。**

站里所有小图标，源文件都在 `icons/` 里，**一个图标一个文件，文件名就是代码里引用的名字**。
但页面**不直接读这些文件**——它们会被打包进 `data/icons.js`，变成写死在 JS 里的内联数据。

为什么要多这一步？因为图标是用 `mask` 渲染的，而**浏览器会把 `mask` 引用的文件当成跨源资源**。
双击打开时是 `file://` 协议，每个本地文件都算「另一个源」，于是文件的图标一律被拦掉，
而且失败得很安静——不是裂图、不是方块，是**整个图标直接消失**。
打包成内联数据就绕开了这个限制，双击也能正常显示。

所以换图标的完整流程是：

1. 把新文件丢进 `icons/`，文件名改成要替换的那个名字（比如 `home.png`）
2. 双击 `icon更新.bat`（等价于在命令行跑 `node tools/build-icons.js`）
3. 刷新页面

`data/icons.js` 是脚本生成的文件，**别手改**，下次打包会被覆盖。

| 用途 | 名字 |
|---|---|
| 侧边栏导航 | `home` `posts` `archive` `works` `downloads` `about` |
| 首页分类卡 | `tech` `life` `notes` `works` |
| 主题按钮三态 | `theme-auto` `theme-light` `theme-dark` |
| 各处的零散图标 | `bolt` `compass` `file` `folder` `mail` `image` |

#### 两套图标，改一个字母就换

`icons/` 里现在**两套图标并存**，同名不同后缀：

| 后缀 | 来源 | 长相 |
|---|---|---|
| `.png` | Icons8 Fluent | Win11 风格，圆润、笔画偏粗 |
| `.svg` | 手绘线条版 | 更细更简，和上一套混着看风格会不统一 |

两套**都已经打包进 `data/icons.js`** 了，所以切换只是改 `SITE` 里一个值，**不用重新打包**：

```js
iconDir: './icons/',   // 打包时的来源路径，也是没打包进去的图标的兜底
iconExt: '.png',       // '.png' 或 '.svg'，改完刷新即生效
```

（`iconDir` 改回 `null` 就退回用文字占位，图标整个不显示。）

#### 两个坑

> 💡 **图标是 `mask` 渲染的，不是 `<img>`。** 只取形状，颜色由网页按当前主题给
> （`currentColor`）——所以亮色暗色下图标会自己变色，**不用准备两套图**。
> 代价是**图片文件里填什么颜色都会被忽略**，黑的白的渲染出来一模一样。

> ⚠️ **图标出问题有两种长得完全不同的表现，别搞混：**
>
> | 你看到的 | 原因 |
> |---|---|
> | 图标**整个消失**，位置空着 | 名字对不上（拼错 / 没打包进去），mask 当成透明 |
> | 图标位置一个**实心方块** | `--ico` 变量是空的或无效，`mask` 整条失效，露出了底下的背景色 |
>
> 第二种基本只会出现在你自己改了 CSS 的时候。第一种就去对上面那张名字表，
> 确认改完图标后**重新跑了「icon更新.bat」**。
> 命名的详细规则见 `icons/README.txt`；`file://` 那套原因写在 `tools/build-icons.js` 开头。

### 下载清单（`files/` 文件夹 + `data/files.js`）

**先说结论：往 `files/` 里加了或删了文件之后，要双击一次「更新下载列表.bat」。**

下载页（`#/downloads`）列的文件，数据来自 `data/files.js` 里的 `FILES` 数组。
那玩意儿不用手写：

1. 把文件丢进 `files/`（想分类就建子文件夹，一层两层都行）
2. 双击 `更新下载列表.bat`（等价于在命令行跑 `node tools/build-files.js`）
3. 脚本问「现在提交并推送到 GitHub 吗」，按 `y` —— 推上去 Netlify 自己会重新部署

脚本扫一遍 `files/`，把结果整个重写进 `data/files.js`。它管什么、不管什么：

| 它管 | 它不管 |
|---|---|
| 扫出 `files/` 下所有文件，按路径写进 `FILES` | `const FILES` **上面**那段注释，一个字不动 |
| 文件大小 `size` —— 每次按实际大小重算 | 你手写的显示名 `name` 和说明 `desc`，原样保住 |
| 时间 `time` —— 只给**新条目**盖一次 | 已经登记过的条目，时间不再动 |
| 认出哪些文件已经没了，从清单里划掉 | `file` 写成 `https://…` 的**外链条目**，完全不碰 |

**文件夹不用单独声明。** `files/game/弹球.zip` 会自动归到「game」—— 文件夹名是从
路径里推出来的（`app/util.js` 的 `folderOf()`）。所以脚本**不写** `folder` 字段：
路径已经说明了一切，写了反而多一处可能对不上的地方。

**`time` 记的是「什么时候登记进来的」，不是文件的修改时间。** 下载页的「◷ 时间」
排序靠它，文件名底下那行小字（`大小 · 时间 · 说明`）里显示的也是它；文件夹那一行
显示的是组里最新的那个时间。脚本认出来的老条目一律沿用清单里原来那个时间，既不去读文件的 mtime，
也不刷成今天 —— 两个原因：每跑一次都重读的话，整张表会被刷成今天，排序成了一锅粥；
而且别人 clone 你的仓库时，所有文件的 mtime 都是 checkout 那一刻，等于全员同一个时间。

> ⚠️ **两条安全绳，知道一下就行。** `files/` 里一个文件都没扫到、但清单里原有条目时，
> 脚本会停下来问你要不要清空，别手快按 `y`；`data/files.js` 要是被改得读不出来
> （语法错），脚本会告诉你手写的条目会丢，这时候 Ctrl+C 退出还来得及。

> 💡 **`const FILES` 数组里面别写注释。** 数组每次都是整个重新生成的，写在里面会被冲掉；
> 数组上面那段是安全的。

## 三、发布到互联网

三个都免费，都不需要备案（服务器在境外）。**推荐第一个**。

### 方案 A：Cloudflare Pages（推荐）

1. 注册 [dash.cloudflare.com](https://dash.cloudflare.com)
2. 左侧 **Workers & Pages** → **Create** → **Pages** → **Upload assets**
3. 项目名随便起，比如 `kili-blog`
4. 把 `index.html` 连同 `styles/` `data/` `app/` `icons/` `files/` 和两张 `bg*.svg`、
   `favicon.svg` **一起**拖进去（**拖文件夹里的内容，不是拖文件夹本身**）
5. 传完给你一个 `xxx.pages.dev` 的网址，能直接访问

> `tools/` 和 `icon更新.bat` 不用传——那是本地打包用的，线上不需要，
> 传上去也无害。`data/icons.js` 一定要传，它是图标真正生效的地方。

想绑自己的域名，在项目的 **Custom domains** 里加就行。免费版带宽不限。

### 方案 B：GitHub Pages

1. 建一个仓库，名字随便
2. 把文件传上去
3. 仓库 **Settings** → **Pages** → Source 选 `main` 分支 `/ (root)` → Save
4. 等一分钟，网址是 `你的用户名.github.io/仓库名/`

> 用这个方案要确认所有路径都是相对路径 —— 你的文件已经全是 `./` 开头的了，
> 不用改。但如果以后自己加东西，别用 `/xxx` 这种绝对路径。

> ⚠️ **`styles/` 里的 CSS 有个反直觉的地方**：CSS 文件里写的相对路径，
> 是相对**那个 CSS 文件自己**算的，不是相对 `index.html`。所以背景图和图标
> 没写死在 CSS 里，而是由 `app/effects.js` 运行时换算成绝对路径再塞进变量
> （`bootBackground()` 和 `bootIcons()`）——这样不管文件放几层深都不会错。
> 你自己加图片的话，要么照这个套路走 JS，要么把路径写成相对 CSS 文件的那一份。

### 方案 C：Vercel

和 Cloudflare Pages 差不多，`vercel.com` 注册后拖文件夹即可。

## 四、关于那个域名 `www.kili白麟.com`

这事得说清楚：**中文域名能注册，但比英文的麻烦。**

- 域名里混了中文和英文（`kili白麟`），这叫国际化域名（IDN）。注册商在后台
  存的是 punycode，也就是 `xn--kili-xxxx.com` 这种形式，浏览器地址栏里
  显示成什么各家不一样。
- 不是所有注册商都支持「中英混排」的标签，有些只允许纯中文或纯英文。
  买之前先在注册商网站上试着查一下能不能搜到。
- 价格大概 ¥30–70/年。国内注册商（阿里云、腾讯云）买 `.com` 需要实名认证；
  国外注册商（Cloudflare Registrar、Namecheap）不需要，但不能用支付宝/微信。
- **`.com` 配中文域名，国内部分邮箱和论坛可能显示异常**，做好心理准备。

**我的建议**：先花一分钟查 `kili白麟.com` 能不能注册。能，就买；
不能，退一步用 `kilibailin.com` 这类纯拼音的，一样便宜、还少一堆麻烦。
先把网站用 Cloudflare Pages 的免费 `xxx.pages.dev` 网址跑起来，
域名的事想清楚了再绑 —— 绑域名随时都能加，不影响已经发出去的内容。

## 五、这个站点为什么这么写

- **零依赖、无构建**：不引任何 CDN，不装任何包，没有 `npm install` 这一步，
  断网也能打开，换任何托管都不挑，十年后大概率还能跑。
  （拆成 `styles/` `data/` `app/` 只是为了好改，不是引入了什么工程化——
   全是浏览器直接吃的 `.css` 和 `.js`，双击 `index.html` 就跑。）
- **不用框架**：整个站点只有「当前在哪个页面」和「亮色还是暗色」两个状态，
  用 hash 路由 + `innerHTML` 一百行就够了。为了这点状态引入 Vue，
  只会让你多出 40MB 的 `node_modules` 和一整套构建流程。
- **文章写在数组里**：没有后台，加文章得手动编辑文件。个人博客一年写不了
  几十篇，这点手工成本比维护一套 CMS 划算得多。

想加评论、全文搜索、实时预览的时候，就是该换框架的时候了。现在还没到。

## 六、想改代码的话

前面几节都是「用这个站」。这一节是「改这个站」—— 记的是那些
**光看代码看不出来、删了就会出事**的东西。

原先这些东西是以注释的形式写在各个 `.js` / `.css` 文件里的。为了让单个文件
别太长，注释精简掉了，内容归到这儿 —— 顺序大致按「从整体到细节」。

### 6.1 文件是怎么拆的

原来整个站是一个 `index.html`。现在拆成了 **17 个 JS + 6 个 CSS**。

拆法是**连续切片**：照着原来的行顺序一刀一刀切开，一行都没有重排、没有改写过。
所以「按新顺序把文件拼回去」和原来的单文件是逐字符一致的 —— 这是拆分的验收
标准，不是靠肉眼审查。想验证的话，比对时去掉注释和空白即可。

**加载顺序就是执行顺序。** `index.html` 里那串 `<script defer>` 从上往下跑。
`defer` 保证了这一点；不加 `defer` 的话谁下载完谁先执行，顺序就乱了。所以：

- `data/` 那七个文件必须排在 `app/` 前面 —— `app/` 里的代码从头到尾都在用
  `SITE`、`POSTS`、`CATEGORIES` 这些常量，而 `main.js` 一跑起来就要用到它们；
- `app/main.js` 必须排在最后 —— 它是启动序列，要等所有函数都定义好。

**为什么拆开了还看得见彼此。** 这些都是「传统脚本」（不是 `type="module"`）。
传统脚本顶层声明的 `function`、`var`、`let`、`const` 全部进同一个全局作用域，
跨文件直接就能用 —— `main.js` 里调 `bootIcons()`、`view-posts.js` 里读 `POSTS`，
靠的都是这个。

> ⚠️ **加新文件时**：在 `index.html` 里补一行
> `<script src="./app/xxx.js" defer></script>`，位置要和它的依赖对上。
> 另外 `let` / `const` 有暂时性死区 —— 同文件里也必须先定义后使用，
> 不像 `function` 那样可以先调用后定义。

> ⚠️ **别给 `<script>` 加 `type="module"`**。一旦变成模块，每个文件就有了自己
> 的作用域，上面那套「互相看得见」立刻失效，得补一堆 `import` / `export`，
> 而且 `file://` 下模块会被 CORS 拦掉 —— 双击 `index.html` 就打不开了。

### 6.2 启动序列（`app/main.js`）

那个文件一共就十几行，是全站的入口。顺序是有依赖的：

| 调用 | 干什么 | 为什么排这儿 |
|---|---|---|
| `bootIcons()` | 把 `data/icons.js` 摊成一条条 `.ico-名字{--ico:url(…)}` 规则 | 必须排在 `render()` 之前：规则还没注入的话，第一屏的图标会是没颜色的空壳 |
| `bootChrome()` | 顶栏名字、侧边栏导航、页脚，顺带量出顶栏高度 | 里面调了 `paintMark()` 填顶栏方块 |
| `bootSecret()` | 长按 3 秒的彩蛋 | 得等方块填好 |
| `bootRail()` `bootBackground()` | 侧边栏收展、背景图 | |
| `bootTheme()` | 读主题、填主题按钮 | 必须排在 `bootParticles()` **之前**：粒子要按亮/暗取两套不同的颜色 |
| `bootParticles()` | 背景粒子 | 见上 |
| `bootClock()` 起后面那五个 | 时钟、搜索、事件委托、头像翻面、开发者模式 | 都是「绑事件」，不画页面，先后无所谓 |
| `render()` | 画第一屏 | |
| `bootSplash()` | 开场动画 | 最后 —— 它是盖在最上面的一层，等页面画完再起飞 |

> ⚠️ 判断某个函数该排哪儿，标准只有一条：**它依不依赖「别人已经做过什么」。**
> 有，就往后放。

### 6.3 四个反复出现的套路

#### ① 事件委托：往 `#view` 上挂，别往按钮上挂

所有页面都是 `render()` 一句 `innerHTML = …` 整个换掉的。绑在按钮上的监听
会跟着旧 DOM 一起没掉 —— 每次重画都得重绑一遍。

所以站里统一挂在 `#view`（或 `document`）上，靠事件冒泡认目标：

```js
view.addEventListener('click', e => {
  const btn = e.target.closest('[data-copy]')
  if(!btn) return
  …
})
```

「被点的是什么」写在 `data-*` 属性上（`data-copy` / `data-dev-edit` / `data-skind`…）。
视图那一层只负责把这些属性画出来，真正的行为集中在 `bootDelegates()` 里 ——
和 `views.js` 里那句「开发者模式的小控件只负责画，点击统一在 boot 里委托」是一回事。

> ⚠️ 新加可点的东西时照这个路子走。直接挂到元素自己身上的话，
> 第一次渲染能点，页面一重画就失效了。

#### ② 捕获阶段：有些点击必须在半路截下来

`addEventListener` 的第三个参数写 `true` 就是**捕获阶段** —— 事件从 `document`
往下走的时候先经过你，等它冒泡回到底下的链接上就晚了。

站里有两处用到：

- **点图片换图**（`app/dev.js`）：文章卡片是整框可点的，封面下面就是那个
  拉伸链接，不截的话点封面直接跳走了。而且**封面不一定有 `<img>`** —— 没填
  `cover` 的文章渲染的是占位块，只认 `<img>` 认不出它，点击照样会穿透过去。
  所以这一段先认 `<img>`，再认 `.cover[data-cover-key]`，两条都截。
  截下来之后 `preventDefault` + `stopPropagation`，链接就收不到这一下。
- **封面图加载失败**（`app/boot.js`）：`error` 事件**不冒泡**，挂在 `#view` 上
  根本收不到，只能走捕获。收到的处理是把整个 `.cover` 换成一张「图片」图标。

> ⚠️ 所以别在模板里再给封面图写 `onerror` —— 两边会打架，
> 而且模板里那条没有捕获阶段这条管用。

#### ③ 拉伸链接：整张卡片可点，但不是「把卡片做成 `<a>`」

卡片里有标签链接，而 `<a>` 里套 `<a>` 是非法 HTML，浏览器会把它们拆开 ——
点哪儿都可能跳错。用的是「拉伸链接」：标题那个 `<a>` 挂 `.stretch`，
它的 `::after` 铺满整张卡片（`.card` 本来就是 `position:relative`）。
于是点卡片空白处、封面、摘要，冒泡上去都是这个 `<a>`，等于整框可点。

> ⚠️ 代价是那层 `::after` 盖在所有东西上面。**卡片里任何要单独点得到的东西，
> 都得抬 `z-index`**：标签 `.chip` 是 `2`，开发者模式那两个按钮是 `3`，
> 封面在开发者模式下也是 `2`（`html.dev-on .card .cover` —— 只在开发者模式开着时
> 抬，普通访客点封面仍旧是进文章）。以后往卡片里加新的可点元素，记得再往上加一层。
>
> 📌 抬了 `z-index` 只是**点得到**，还得 JS 那边认得出这是什么东西（封面的
> `data-cover-key` 就是干这个的）。两半缺一个，表现都是「点了没反应 / 跳走了」。

归档视图里是例外：那一行本来就是个整行链接，就没再套拉伸链接，直接
把「编辑 / 删除」按钮塞在 `<a>` 里面了（严格说也是非法 HTML，但浏览器不拆它，
能用）。真要在那一行里再加东西，请改成「普通 `div` + 拉伸链接」那套 ——
网站导航页的 `.site-link` 就是标准写法。

#### ④ `afterPaint()`：画完页面之后还要做的事

`paintView()`（`app/router.js`）每次画完视图会做两件事：

```js
applyImgMap()      // 把开发者模式换过的图片替换上去
runAfterPaint()    // 跑注册进来的钩子
```

第一件是直接调的：视图是整个 `innerHTML` 换掉的，不扫这一遍，
换过的图一刷新就打回原形。

第二件是**注册制**的 —— 目前只有一个钩子（文章编辑页的实时预览初稿），
在 `app/dev.js` 里一句 `afterPaint(paintPreview)` 挂上去。

之所以用注册制、而不是在 `router.js` 里写死「画完调 A、再调 B」：路由那一层的
职责就是「按地址栏决定画哪一页」，不该知道开发者模式和文章预览这些事。
要加新钩子，在 `boot.js` 里 `afterPaint(fn)` 一句就行，不用回头动路由。

> 钩子里抛异常不影响别的钩子，也不影响页面 —— 一个附加效果崩了，
> 不该把整页拖下水。

### 6.4 中文用户才会碰到的三个坑

**① 中文输入法拼字途中会连着触发 `input` 事件。**
在搜索框里打「白」，拼音 `bai` 的每一次按键都会触发一次 `input`，
不过滤的话每敲一下就重画一次页面：

```js
q.addEventListener('input', e => {
  if(e.isComposing) return    // ⚠️ 拼字途中，别动
  …
})
```

`isComposing` 是浏览器给的「正在拼字」标记。回车那处也判了一次 ——
拼字途中的回车是「选字」，不是「搜索」。

**② 地址栏里的 hash 是能被随手改坏的。**
`decodeURIComponent()` 碰上坏的百分号转义会直接抛 `URIError`，
而 hash 就在地址栏里。所以包了一层，坏链接退化成原文 ——
难看总好过整个页面白屏。

**③ `.bat` 文件必须是 CRLF 换行，不然中文会炸。**
`icon更新.bat` 和 `更新下载列表.bat` 里都有中文提示，而 `cmd.exe` 读 `.bat`
时是**按行**解析的 —— LF-only 的文件它认不全，中文字节和行边界对不上，
结果是 `echo` 那行被拆成好几截，后半截被当成命令去执行：

> `'件夹，更新' 不是内部或外部命令`
> `'rlevel' 不是内部或外部命令`

连 `if errorlevel 1 (...)` 这种括号块也会被拆坏。表现是双击之后窗口一闪，
图标没更新、清单也没变，看着像没反应。

加 BOM 不管用，**只有 CRLF 管用**（实测过：只加 BOM 照样乱，只改成 CRLF 就正常）。

所以动这两个 `.bat` 的时候，要确认存下来的换行符是 CRLF。用编辑器改完
回头验一下，`file 更新下载列表.bat` 应该报 `UTF-8 Unicode text, with CRLF line terminators`。

### 6.5 搜索页那几行「看着多余」的写法，删了会出事

都在 `app/view-home.js` 里，三处：

**① 不能写 `.map(workCard)`，必须写 `.map(w => workCard(w, q))`。**
`Array.map` 会把**下标**当第二个参数传进去，`q` 就变成了 `0 / 1 / 2`，
于是整张卡片的文字都会被当成搜索词，一段一段全被高亮。文章卡片、文件行同理。

**② 判断「有没有东西可看」要用 `shownCount`，不能用 `total`。**
选中「文件」这一类时，文章和作品的命中数不该算数 —— 用 `total` 的话会出现
「标签上写着共 2 条，屏幕上却一片空白」。用 `shownCount` 才会正常显示空状态。

**③ 取正文纯文本要用 `plain()`，不能用 `md()`。**
`md()` 会把全局的 `MD_TOC` 重置掉（文章详情页的目录就靠它），
在搜索页上跑一遍，那边目录就错乱了。

### 6.6 CSS 里几个反直觉的地方

**`:root` 不能写成 `html`。** 窄屏那几条媒体查询要覆盖桌面版的侧边栏宽度，
选择器必须写 `:root`：它是伪类，优先级 `(0,1,0)`；`html` 只是类型选择器，
`(0,0,1)` —— 根本盖不住，手机上会继续用桌面那份 72px 的栏宽、92px 的让位。
（这个坑真踩过：窄屏一直没生效，页面上能看见左边空出一大条。）
`--edge` 得单独再写一份：侧边栏在手机上要变成贴边的底部横条，
但顶栏该留的那道缝还得留着。

**`opacity` 小于 1 又不是定位元素的，会被当成定位元素来画。**
这是 CSS 规范里的一条，顶栏方块炸齿轮那段就栽在上面：方块脸 `.mark-face`
一旦 `opacity:0`，就按「`z-index:0` 的定位元素」参与层叠，反而压到没定位的
齿轮按钮头上 —— 于是齿轮只能点开一次，等动画一撤点击就全被截胡。
修法是给齿轮一个正的 `z-index`，再配一条 `pointer-events:none`，两道保险。

**玻璃材质的 `background` 必须拆成 `background-color` + `background-image`。**
方格纸纹理是走 `background-image` 叠上去的，写成简写 `background:` 的话，
`hover` 那一条会把纹理整个冲掉。`.card` 的 `hover` 同理。

**方格纹理走 `background-image`，不用 `::after`。** 绝对定位的伪元素会盖在
没定位的正文上面，还得跟 `z-index` 打架。

**不支持毛玻璃的浏览器要兜底。** `styles/base.css` 里有一段
`@supports not (backdrop-filter:…)`，把面板调实保证能看清。里面一共三份：
亮色 `:root`、暗色 `html[data-theme="dark"]`，还有一条
`@media (prefers-color-scheme:dark)` —— 最后这条必须写在最里面、最后面：
它的选择器是 `html:not([data-theme="light"])`，优先级比 `:root` 高，
同优先级下只有后写的才赢。漏掉它的话，「系统开了深色 + 浏览器不支持毛玻璃」
的用户会拿到半透明面板叠在花背景上，正好是这段兜底要防的情况。

### 6.7 为什么有几件事**没**做

**没用 `@layer`。** `@layer` 能让层序压过优先级，是整理 CSS 的好工具，
但它会**翻转跨文件的覆盖关系** —— 现在靠「后写的赢 / 优先级高的赢」维持的
那批覆盖，套上 `@layer` 之后得逐条重新推一遍。这个站一共六个样式文件、
规则量不大，收益抵不上风险。

**没用 `fetch` 读 JSON。** 双击 `index.html` 打开时是 `file://` 协议，
`fetch` 本地 json 会被浏览器拦掉。所以数据写成 `.js` 里的 `const` ——
浏览器直接当脚本执行，不受协议限制。（`data/icons.js` 把图标内联成
`data: URI` 也是同一个原因：`mask` 引用的文件会被当成跨源资源，`file://`
下直接不显示。）

**没有 `.glass` 公共类。** 玻璃材质不是封装在一个类里的，而是拆成几个
CSS 变量（`--panel` / `--panel-shadow` / `--glass-bevel` / `--glass-sheen` /
`--blur`），各个面板各自引用。以前有过一个 `.glass` 类，全站一处都没引用，
是死代码，已经删了。

**开发者模式没有密码。** 见第二节「开发者模式」开头那段：静态站没有服务器，
「验证」只能发生在访问者自己的浏览器里，必然能被绕过。与其摆一道假门，
不如说清楚它到底能干什么、改的东西存在哪儿。
